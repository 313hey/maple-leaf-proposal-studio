# 景点图片迁移方案（待单独实施）

目前景点图片嵌在 `studio_attractions.payload.images` 中。本轮只按需读取图片，未改变现有图片或数据库结构。

未来若迁至 Supabase Storage，先新建私有图片桶及缩略图生成流程，再为景点增加可选的图片引用字段。读取时优先使用引用，缺失或加载失败时继续读取旧版 Base64。上传新图片时先确认对象上传成功，再提交景点记录；旧字段暂时保留，避免部分写入造成图片丢失。

迁移程序应逐条处理，记录资源 ID、原图摘要、对象路径、上传校验结果和失败原因。先用数据副本验证图片数量、尺寸、封面顺序和 Proposal 中的独立景点副本；再小批量灰度。迁移期间不覆盖已被同事更新的记录，提交前比较 `updated_at`。备份完整资源库和对象清单，并在确认所有设备可读取新旧格式后才讨论清理旧字段。旧 Base64 图片的删除需要另行审批，且应保留回滚窗口。
